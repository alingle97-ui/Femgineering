Templates for Topics

Lesson 3 · Femgineering Dashboard

Your /topics route works, but look at how it's built: HTML tags glued together inside Python strings with +=. That's fine for two topics. It gets miserable fast — imagine writing the Episodes page with statuses, guest names, and dates all tangled into one string. This lesson fixes that by introducing templates: real, separate HTML files that Flask fills in with your data. Python handles data, HTML handles layout — each in its own file, which is how real web apps are structured.

What a template is

A template is an HTML file with placeholders in it, using a syntax called Jinja (Jinja comes bundled with Flask — nothing new to install). Two kinds of placeholders you'll use today:

  • {{ something }} — double curly braces print a value. {{ topic.name }} prints that topic's name.
  • {% something %} — curly-brace-percent handles logic, like loops. {% for topic in topics %} ... {% endfor %} loops over a list, same idea as the Python for loop from Lesson 2, just written in the template instead of in Python.

Notice topic.name uses a dot instead of topic['name'] — Jinja lets you use dot notation for dict keys, which reads a little cleaner in a template.

Step 1 — Create the templates folder

Flask looks for templates in one specific place: a folder literally named templates, sitting next to app.py. In your terminal, in the Femgineering folder:

mkdir templates

This name isn't optional — Flask assumes it by default, so it won't find your files if the folder is named anything else.

Step 2 — Write the template

Create a new file templates/topics.html with exactly this:

<h1>Topics</h1>
{% for topic in topics %}
  <h2>{{ topic.name }}</h2>
  <p>{{ topic.why_it_matters }}</p>
{% endfor %}

This is just HTML with two Jinja tags dropped in — no Python here at all. Compare it to the Lesson 2 route: same loop, same two fields, but now it reads like a page instead of a string being assembled piece by piece.

Step 3 — Point the route at it

Back in app.py, update the top import and the /topics route:

from flask import Flask, render_template

# ...keep your existing topics list and other routes...

@app.route("/topics")
def topics_page():
    return render_template("topics.html", topics=topics)

New pieces:

  • render_template — a Flask function that finds a file in your templates folder, fills in its Jinja placeholders, and returns the finished HTML. You have to import it alongside Flask, since it's not there by default.
  • render_template("topics.html", topics=topics) — the first argument is the filename to render. Everything after it is name=value pairs that become available inside the template — topics=topics makes your Python topics list accessible inside topics.html under the name topics. The name on the left is what the template sees; it doesn't have to match the Python variable name on the right, though keeping them the same (like here) is the least confusing.
  • Your whole route is now one line, because all the HTML-building moved into the template file.

Step 4 — Run it

Restart if needed (python3 app.py), then visit http://127.0.0.1:5000/topics — it should look identical to Lesson 2's page. That's the point: same result, much cleaner code behind it.

Win: /topics renders from a real template file instead of a hand-built string — and your route function shrank to one line.

Why bother, if the output looks the same?

Two real reasons, not just tidiness:

  • It scales. Once a page needs more than a couple of fields (Episodes will have title, status, guests, dates), a Python string gets unreadable fast. A template stays readable no matter how much HTML it has.
  • It's safer by default. Jinja automatically escapes special characters in your data — so if a topic name ever contained something like <script>, Jinja shows it as harmless text instead of letting it run as HTML. Building strings by hand with += doesn't protect you from that automatically.

Try it yourself

Before moving on, without looking back at Step 2:

  1. Edit templates/topics.html so each topic's name and "why it matters" are shown inside a bulleted list item (<li>) instead of an <h2>/<p> pair — wrap the whole loop in <ul>...</ul>.
  2. Reload /topics and confirm it now renders as a bulleted list.

You're only touching the template file for this — app.py doesn't need to change at all. That split is exactly what templates are for.
